diagBruit — Validation des alert_slug

Étape 6 du plan d'automatisation des règles PLU — complétion des alert_slug produits par generer_export.py

Mode d'emploi
  1. Chargez etape6_{dept}_export.csv (ou un export précédent de cet outil, pour reprendre une session).
  2. Le champ Alert slug est préempli avec la proposition mécanique (alert-{Territoire}-, partie territoire déjà calculée) — complétez-le directement avec le terme métier (ex. alert-EurometropoledeStrasbourg-exhaussement), ou corrigez-le entièrement si territoire_propose vous semble faux. Voir docs/etape-6-mise-en-forme-diagbruit.md, "Format de l'alert_slug", pour ce que doit être ce terme métier (jamais un résumé du message : un vocable technique du domaine, parfois absent du texte).
  3. Le message final (message_strapi), déjà validé à l'étape 5 qu'il soit natif ou corrigé manuellement, s'affiche en lecture seule pour vous aider à choisir un terme cohérent avec le document concerné.
  4. ↺ revient à la proposition mécanique d'origine si votre saisie ne convient pas.
  5. Exportez régulièrement votre progression — un export automatique se déclenche aussi tous les 10 champs modifiés. Sans sauvegarde navigateur possible dans cet outil, un export non téléchargé = un travail non conservé si l'onglet se ferme.
  6. Le fichier exporté a exactement la même structure que etape6_{dept}_export.csv — une fois la relecture terminée, renommez le dernier export téléchargé pour remplacer etape6_{dept}_export.csv (ou utilisez-le tel quel) : c'est directement le fichier pour la saisie Strapi/Notion, aucun script Python supplémentaire à relancer.
